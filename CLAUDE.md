# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Running the game locally

```sh
cd web
python3 -m http.server 8000
# open http://localhost:8000
```

No build step. All frontend changes take effect on browser reload.

## Generating levels

```sh
# C++ generator (fast, preferred)
clang++ -O3 -std=c++17 tools/generate.cpp tools/difficulty_analyzer.cpp -o tools/generate.exe
tools/generate.exe --sizes 8 9 10 11 12 --count 50 --seed 42

# Python generator (slower, same algorithm)
cd tools
python3 generate.py --sizes 8 9 10 11 12 --count 5 --seed 42

# Always rebuild the browser bundles after generating
python3 build_levelsbundles.py
```

`--count N` overwrites files `001..00N` for each size. To add levels without disturbing existing ones, generate into a scratch dir and copy with higher indices, then rebuild the browser bundles.

## Checking a level

```sh
python3 tools/solver.py levels/8/level_8_001.txt
```

## Printing levels

```sh
# pack 6, levels 1-10 and 51-60, four boards per A4 page -> meowdoku_6.pdf
python3 tools/gen-pdf.py --set 6 --level 1..10,51..60 --per-page 4
```

## Architecture

### Puzzle rules

Place one cat per row, one per column, no two cats touching (including diagonally), exactly one cat per color region. Each level has a unique solution.

### Level files (`levels/<pack>/level_<pack>_<idx>.txt`)

```
8
AABBBCCD
...
# solution: 3 1 6 4 0 7 5 2
```

Letters A–L = region ids 0–11. The `# solution:` comment is ignored by the browser; it's used only by `tools/solver.py`.

A *pack* is either a board size (`6`..`12`, every board that size) or one of the two mixed-size packs, whose board size is read from each file's first line rather than the directory name:

- **`hard`** — pure-logic solvable but needs advanced deductions. These were originally misfiled under `backtrack/` by an analyzer that was missing two deduction rules; see `backtrack_rescued.txt` for the full list and provenance.
- **`bad`** — genuinely unsolvable by logic alone (requires guessing), shipped as an opt-in challenge pack.

Indices are contiguous from 1 within each pack.

### Frontend (`web/`)

Single-page app, no framework, no bundler.

- **`game.js`** — all game logic. Key globals:
  - `REGION_COLORS` — 12 hex colors, index 0 = region A. Wrap-around via `% length` if board needs more.
  - `state` — current puzzle state (board, regions, solution, hearts, gameOver). `state.pack` is the selected pack key, `state.n` the actual board size; for numeric packs they agree, for `hard`/`bad` they don't.
  - `el` — cached DOM references, populated once at script load.
  - `settings` — sound/vibrate/autoElim/dimMarked/copyAscii toggles, persisted in `localStorage("meowdoku_settings")`. `hypo` lives here too but is a per-level scratch mode, not a preference: `startLevel()` always resets it to false.
  - Keyboard shortcuts (game screen only, suppressed while a modal is open): Space toggles 假設 mode, `c` copies the relay link (`?r=`) to the current board. Copying the board as BBS-ready ANSI art is button-only (`#btn-copy-ascii`).
  - Completed levels stored in `localStorage("meowdoku_done")` as `"pack:idx"` → star count (1–3, the hearts left on the winning run).
  - Progress export/import (settings dialog) is deliberately asymmetric: export copies `{v, stars}` JSON to the clipboard, import *merges* a pasted map instead of overwriting, keeping the higher star count per level. Keys for packs the build does not ship are preserved, so importing on an older client never erases a newer one's levels.
- **`styles.css`** — three tunable CSS variables in `:root`: `--cat-scale`, `--mark-scale`, `--mark-thickness` (all in `cqw`, i.e. % of cell width via container queries).
- **`sw.js`** — network-first app shell plus offline level-bundle caching. A new level manifest becomes the offline version only after all referenced bundles pass their SHA-256 and structure checks.
- **`levels/bundle/manifest.json`** — generated by `tools/build_levelsbundles.py`; maps each pack to its level count, bundle file and content hash. Pack button order and display labels (`困難`, `需猜測`) come from `EXTRA_PACKS` / `PACK_LABELS` in `game.js`.

### Input handling

Pointer Events API (`pointerdown/move/up/cancel` on `#board`). The board calls `setPointerCapture` on first touch to own the drag. `e.preventDefault()` is called only after confirming the pointer is over a board cell (not before) so toolbar button clicks are not suppressed on mobile.

### Level generation (`tools/`)

1. `generate.py` / `generate.cpp` — same algorithm: random no-adjacent-column permutation → multi-source BFS flood fill per region → uniqueness check → targeted boundary-cell repair loop (up to 400 iterations) to kill alternate solutions without moving cat cells. C++ is ~12× faster.
2. `solver.py` — pure-Python backtracker used by `generate.py`. The C++ rewrite inlines the solver.
3. `difficulty_analyzer.py` / `difficulty_analyzer.{h,cpp}` — same tier1/tier2/tierk human-reasoning simulation (see the module docstring for tier definitions); the C++ port drops the step-by-step descriptions and is called in-process by `generate.cpp` (no subprocess launch) to reject boards that need backtracking (D9). Keep both in sync if the reasoning rules change; use the Python version for human-readable reports (`--step-by-step`, `--prune`).
4. Levels that fail the D9 check aren't discarded — they're written to `levels/backtrack/level_<n>_<idx>.txt` (flat, mixed sizes) instead of the per-size dirs. This is a staging area: triage new arrivals into the `hard` / `bad` packs (renumbering them `level_<pack>_<idx>.txt`) rather than shipping from it. `build_levelsbundles.py` skips this directory.
5. `build_levelsbundles.py` — validates contiguous level files, normalizes their bundled copies to LF, and writes deterministic per-pack JSON plus `levels/bundle/manifest.json`. The legacy `build_index.py` remains for compatibility but is not used by the browser.

### Printing (`tools/gen-pdf.py`)

Exports boards as a print-ready A4 PDF: colour blocks only, white background, no cats / marks / frames. No third-party dependencies — `PdfDocument` writes the file by hand (filled rounded rectangles, one Flate-compressed content stream per page), which is all a board needs.

- `--set` is a pack key, `--level` takes `1..10,51..60` / `5-9` / `7` / `all`, `--per-page` is 1, 2, 4 or 6. `GRIDS` maps boards-per-page to (rows, cols); the block of boards is centred on the page so every gap is one `GUTTER`.
- Region colours are parsed out of `DEFAULT_REGION_COLORS` in `web/game.js` at run time, so the printed palette cannot drift from the screen one.
- `--label` writes each board's level number under its own bottom-left corner (not one number per page), so the number survives a page being cut into separate puzzles. `slots()` reserves `BoardRenderer.LABEL_SPACE` under every board for it: labels shrink the boards slightly instead of pushing text into the page margin. This is the only text the tool ever draws, and the Helvetica font object is emitted only if something drew some.
- `BoardRenderer` is the seam for new print styles. A black-and-white variant is a known future request and needs a different visualization entirely (hatching, outlines or letters — colour is the only thing separating two regions here): subclass `BoardRenderer`, register it in `RENDERERS`, and level lookup, layout, paging and the CLI are unaffected.

### Tuning colors and icon sizes

- **Region colors**: edit `REGION_COLORS` in `web/game.js`. Keep at least 12 entries (largest board is n=12).
- **Cat/mark sizes**: edit `--cat-scale`, `--mark-scale`, `--mark-thickness` in `:root` in `web/styles.css`. See `develop.md` for details.
